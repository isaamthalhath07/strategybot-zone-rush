# Exact f5 numeric-family adapter

`space.PublicMemoryTemplateSpace()` exports the published Blocker public-memory
correction with the twelve numeric loci and bounds of the original Blocker
exporter. The default export is byte-identical to published
`f5e870cd8bb56024c579d1251943c656daf62d2652c5eba44aee530ba1160405`.
All other exports change only the same canonical class-qualified numeric
literals. Original sources, production and every registered study arm remain
untouched. No candidate file is written by this API.

The interface provides `defaults`, `bounds`, `validate(genes)`, `export(genes)`,
`inspect_export(body)`, `mutate(parent, seed, scale=0.06, max_changes=3)`,
`crossover(first, second, seed)` and `description()`. Source guards bind the
exact original, published fix, builder and numeric exporter. The returned
description includes the source closure and explicit zero credit/status fields.

Its strategy family is `blocker`; its structural template is
`public-memory-blocker`. A scheduler may rank it against other Blockers, but
must first declare which exact structural template a child inherits. Numerical
crossover never chooses, merges or repairs structural source bytes. The adapter
does not authenticate evidence, qualify a policy, select parents or promote it.

The fix removes public contradictions to guessed Shield events and follows
observable own work progress. It does not make genuinely ambiguous rival
cooldowns identifiable. A correct tracker can still produce a weaker policy
under old heuristic weights. See [STRATEGY_REVIEW.md](STRATEGY_REVIEW.md) for the
prospective TRAIN comparisons and rejection criteria.

Run the synthetic source and scripted-memory checks with
`python -m unittest deadline_strategy.test_space -v`. They cover exact defaults,
canonical inspection, deterministic bounded operators, source drift, blocked
accepted moves and hidden-distinct worlds with identical public histories.
These checks play no policy-strength or campaign games and create no GPU,
primary-game, completed per-game BMCTS or promotion credit.

The separate `goal_space.PersistentGoalTemplateSpace()` adds fixed persistent
public goal scores to f5. It is excluded from generation0; the coordinator's
prospective generation1 declaration requires its exact f5 control and prior
correctness/runtime qualification. See [GOAL_CANDIDATE.md](GOAL_CANDIDATE.md)
for the fixed equations, source pin and limitations, and
[TRAIN_ANALYSIS.md](TRAIN_ANALYSIS.md) for complete-generation reporting and
the promotion rule's interpretation. Its parameters are not fitted on heldout
outcomes, and this package cannot authorize its use by itself.
