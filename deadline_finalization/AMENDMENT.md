# Prospective unchanged-evidence finalization amendment

This is an execution amendment to the separate ten-hour campaign. It changes no existing source, policy, physics, source-family recipe, map allocation, statistical rule, deadline or game-admission requirement. The original 53 pinned files remain unchanged. This package must be source-pinned, reviewed, published and explicitly owner-sealed before any heldout reservation or outcome. Merely importing it activates nothing.

Finalization currently reparses every completed generation's complete proof logs at each phase boundary. This adapter performs the same full original validation once per cache certificate, then permits reuse only while the exact verified bytes remain unchanged. New work always receives all original callbacks, all 320 independent replay callbacks per game and both CPU referees. Cached reads create zero games, callbacks, physical steps, primary credit or BMCTS credit.

An owner-sealed amendment uses the existing `registration` scope with a distinct format and role. It binds the original campaign/manifest and 53-file closure, the adapter source hashes, original function code/default/closure contracts, exact execution configuration and the four fixed qualified rival sources. In particular it adds an explicit qualified-racer byte check; it does not pretend that racer is directly in the old 53-file closure. Publication after any shortlist/heldout phase marker is rejected.

Each certificate uses the existing `acceptance` scope with a distinct cache format/role and zero-credit fields. It contains the fully checked parsed summary/aggregate and their digests, exact registration and actual accepted-receipt hashes, CPU Python runtime, configuration, source closures and a complete proof tree. Certification validates the exact canonical stage registration and receipt, runs the original full `_validate_acceptance` code with a passive capture of the original `_verify_output` result, and requires identical byte hashes before and after that validation. No caller Boolean or substitute authority can mint a certificate. Actual operations require the exact owner-local authority type; synthetic tests explicitly substitute only their fake fixture boundary.

The tree includes every file and directory under `execution`, every candidate file, and the stage registration, registration seal/receipt, start and accepted receipts. Missing, extra, renamed, changed, linked or failed proof artifacts reject reuse. A stage-level failure receipt also rejects reuse. Only `report.json` and `report.sha256` are declared optional analysis outputs; they are not consumed by phase decisions and are excluded from the cached evidence tree. No other stage-root member is silently excluded.

Every read verifies the owner MAC and amendment, current adapter/original code, CPU Python runtime, configuration, qualified rivals, exact registration and accepted receipt, and rehashes every proof file's actual bytes. Size and modification times never substitute for hashing. The current full tree must exactly equal the certified tree, and the cached summary must hash to the raw checked summary file. Data returned to the frozen phase code is an isolated copy. Missing or invalid certificates fail closed; there is no automatic verification fallback, certificate overwrite or partial-cache admission.

The phase adapter creates new function objects from the original controller functions' exact code/defaults/closures in one copied globals dictionary. All helper calls therefore share the declared cache reader. Only `_verify_output` is replaced by the verified cache read; `_execute` is explicitly restored to the ORIGINAL function object with its ORIGINAL globals. Thus fresh DEV/FINAL execution still calls the original full verifier. The frozen registration, accepted-receipt, lineage, shortlist, source, time, field, statistic and fallback checks remain in the call graph. No original module globals are modified.

The owner must keep completed proof trees immutable while checks and phases run. Before/after hashing detects ordinary certification-time changes, and reuse hashes detect later changes; this does not provide an adversarial concurrent-writer, hostile-host or hardware attestation. The MAC certifies the trusted owner's successful validation and exact byte identity. A root operator may deliberately use the untouched original controller for full revalidation instead, subject to the same cutoffs; an invalid cache is never a reason to skip checks.

At the initial read-only GEN0 profile, the scanner rehashed 559 proof files and checked 68 directories in 1.8924 seconds. It executed no key operation, certificate creation, actor callback or physical replay. This is an observed hash-scan cost, not a guaranteed end-to-end phase time: canonical cohort reconstruction, MAC checks, architecture revalidation and other original phase work remain. The owner must preserve adequate finalization and packaging headroom.
